## MA101

`comptime-unroll` severity=low confidence=medium risk=codesize (larger code / compile time)

Small constant trip-count loop in hot code: `comptime for` guarantees unrolling and makes the index a compile-time value (cheap SIMD lane access, usable as a parameter).

Bad:

```mojo
for l in range(4):
    s += v[l]
```

Good:

```mojo
comptime for l in range(4):
    s += v[l]
```

## MA102

`vectorize-elementwise` severity=medium confidence=high risk=none (no semantic change)

Elementwise loop over float buffers with no loop-carried dependency: use `vectorize` with `simd_width_of`. Results are bit-identical (no reassociation).

Bad:

```mojo
for i in range(n):
    y[i] = a * x[i] + y[i]
```

Good:

```mojo
vectorize[simd_width_of[DType.float64]()](n, body)  # body: unsafe_load/unsafe_store[width=w]
```

## MA103

`simd-reduction` severity=medium confidence=high risk=fp (changes FP rounding (not bit-exact))

Scalar float reduction (`s += f(x[i])`, `m = max(m, x[i])`): use SIMD accumulators + `reduce_add`/ `reduce_max`. Sums are reassociated, so results change in the last bits; min/max are exact.

Bad:

```mojo
for i in range(n):
    s += a[i] * b[i]
```

Good:

```mojo
acc += pa.unsafe_load[width=w](i) * pb.unsafe_load[width=w](i)  # then acc.reduce_add()
```

## MA104

`literal-simd-width` severity=low confidence=high risk=none (no semantic change)

Hardcoded SIMD width passed to `vectorize`/`width=`: use `simd_width_of[DType]()` so the width follows the target (AVX2/AVX-512/NEON) and stays autotune-friendly.

Bad:

```mojo
vectorize[8](n, body)
```

Good:

```mojo
vectorize[simd_width_of[DType.float32]()](n, body)
```

## MA105

`parallelize-candidate` severity=medium confidence=medium risk=threads (concurrency: verify callees are thread-safe)

Outer loop whose iterations are independent (each writes only `out[i]` and locals, calls only pure builtins / read-only project functions) and do heavy work (nested loop): candidate for `parallelize`.

Bad:

```mojo
for i in range(n):
    out[i] = heavy(i)
```

Good:

```mojo
def job(i: Int) {mut op}:
    op[i] = heavy(i)
parallelize(job, n)
```

## MA106

`list-reserve` severity=medium confidence=high risk=none (no semantic change)

Empty `List` filled by an unconditional `append` in the loop that immediately follows: the count is known, so allocate once (`List[T](capacity=n)`, or `length=n, fill=v` for a constant).

Bad:

```mojo
var xs = List[Int]()
for i in range(n):
    xs.append(f(i))
```

Good:

```mojo
var xs = List[Int](capacity=n)
for i in range(n):
    xs.append(f(i))
```

## MA107

`string-concat-loop` severity=low confidence=high risk=none (no semantic change)

String built with `+`/`String(x)` temporaries inside a loop: each iteration allocates temporaries. Append in place with `s.write(a, b, ...)`.

Bad:

```mojo
for i in range(n):
    s += String(i) + ","
```

Good:

```mojo
for i in range(n):
    s.write(i, ",")
```

## MA108

`dict-double-lookup` severity=low confidence=high risk=none (no semantic change)

`if k in d:` followed by `d[k]`: two hash lookups (and `d[k]` raises). Use one `d.find(k)`.

Bad:

```mojo
if k in d:
    s += d[k]
```

Good:

```mojo
var v = d.find(k)
if v:
    s += v.value()
```

## MA109

`copy-in-loop` severity=medium confidence=high risk=none (no semantic change)

`var x = expr.copy()` inside a loop where `x` is only read: bind a reference instead (`ref x = expr`), avoiding a deep copy (allocation) per iteration.

Bad:

```mojo
for i in range(n):
    var row = rows[i].copy()
    s += row[0]
```

Good:

```mojo
for i in range(n):
    ref row = rows[i]
    s += row[0]
```

## MA110

`owned-arg-read-only` severity=low confidence=high risk=api (signature change)

`var` (owned) argument of a heap type that the body only reads: callers must copy or move into it. Use the default read convention; existing `f(x^)` call sites still compile.

Bad:

```mojo
def total(var xs: List[Float64]) -> Float64:
    return xs[0]
```

Good:

```mojo
def total(xs: List[Float64]) -> Float64:
    return xs[0]
```

## MA111

`iterate-directly` severity=low confidence=high risk=none (no semantic change)

`for i in range(len(xs))` where `i` is only used as `xs[i]` (reads): iterate the list directly; no bounds checks, no semantic change.

Bad:

```mojo
for i in range(len(xs)):
    s += xs[i]
```

Good:

```mojo
for x in xs:
    s += x
```

## MA112

`reciprocal-multiply` severity=low confidence=medium risk=fp (changes FP rounding (not bit-exact))

Float division by a loop-invariant value inside a loop: hoist `inv = 1.0 / d` and multiply (div is ~4-20x the latency/throughput of mul). Not bit-exact.

Bad:

```mojo
for i in range(n):
    y[i] = x[i] / d
```

Good:

```mojo
var inv = 1.0 / d
for i in range(n):
    y[i] = x[i] * inv
```

## MA113

`unsafe-ptr-inner-loop` severity=medium confidence=high risk=unsafe (bounds checks removed)

Bounds-checked `List` indexing in an inner loop (List `__getitem__` asserts by default, which also blocks auto-vectorization): take `unsafe_ptr()` once before the loop.

Bad:

```mojo
for j in range(m):
    s += w[j] * x[j]
```

Good:

```mojo
var wp = w.unsafe_ptr()
for j in range(m):
    s += wp[j] * x[j]
```

## MA114

`loop-interchange` severity=high confidence=high risk=none (no semantic change)

Perfectly nested loops traversing a row-major buffer column-wise (inner index has a non-unit stride, outer index is unit-stride): swap the loops. Only flagged when the swap is legal and bit-exact (writes are per-element, accumulation order per element is preserved).

Bad:

```mojo
for j in range(m):
    for i in range(n):
        s[j] += a[i * m + j]
```

Good:

```mojo
for i in range(n):
    for j in range(m):
        s[j] += a[i * m + j]
```

## MA115

`list-front-ops` severity=high confidence=high risk=none (no semantic change)

`List.insert(0, x)` / `List.pop(0)` in a loop are O(n) each (O(n^2) total): use `Deque` (`appendleft`/`popleft`).

Bad:

```mojo
for i in range(n):
    xs.insert(0, i)
```

Good:

```mojo
var xs = Deque[Int]()
for i in range(n):
    xs.appendleft(i)
```

## MA116

`list-membership` severity=medium confidence=medium risk=none (no semantic change)

`x in xs` on a `List` inside a loop is a linear scan: keep a `Set` (or `Dict`) for membership.

Bad:

```mojo
for i in range(n):
    if i in seen:  # seen: List[Int]
        hits += 1
```

Good:

```mojo
var seen = Set[Int]()  # ...
for i in range(n):
    if i in seen:
        hits += 1
```

## MA117

`redundant-gpu-sync` severity=low confidence=high risk=none (no semantic change)

`ctx.synchronize()` immediately followed by another `ctx.enqueue_*` on the same context: the stream is in-order and the host does nothing in between, so the sync only adds a host round-trip.

Bad:

```mojo
ctx.enqueue_copy(dev, host)
ctx.synchronize()
ctx.enqueue_function[k](dev, grid_dim=g, block_dim=b)
```

Good:

```mojo
ctx.enqueue_copy(dev, host)
ctx.enqueue_function[k](dev, grid_dim=g, block_dim=b)
```

## MA118

`literal-arg-to-param` severity=info confidence=low risk=api (signature change)

Function argument that every call site in the analyzed files passes as an integer/bool literal and that drives control flow (`range`, `if`, `while`): make it a compile-time parameter so the branch/trip count folds. One instantiation per distinct value.

Bad:

```mojo
def f(x: List[Float64], k: Int): for i in range(k): ...
f(a, 4); f(b, 8)
```

Good:

```mojo
def f[k: Int](x: List[Float64]): comptime for i in range(k): ...
f[4](a); f[8](b)
```

## MA119

`copy-into-read-arg` severity=low confidence=high risk=none (no semantic change)

`f(x.copy())` where `f` takes that argument by the default read convention: the copy is discarded unread. Pass `x` directly.

Bad:

```mojo
def f(xs: List[Int]) -> Int: ...
f(ys.copy())
```

Good:

```mojo
f(ys)
```

## MA120

`aos-field-loop` severity=low confidence=medium risk=api (signature change)

Hot loop reading one or two fields of every element of a `List[Struct]` with many fields: each element's whole cache footprint is streamed to use a few bytes of it. Keep the hot fields in their own `List` (SoA).

Why: an 8-field Bar is 64 B per element; summing .close reads 8 B of it (measured 2.3-7.5x)

Bad:

```mojo
for i in range(len(bars)):
    s += bars[i].close  # Bar has 8 fields
```

Good:

```mojo
for i in range(len(close)):
    s += close[i]  # close: List[Float64]
```

## MA121

`struct-padding` severity=info confidence=high risk=api (signature change)

Struct fields in an order that forces alignment padding (Mojo keeps declaration order): sorting fields by size (largest first) shrinks every element, which matters for large `List[Struct]` buffers.

Bad:

```mojo
struct A:
    var a: Bool
    var b: Float64
    var c: Bool
    var d: Float64  # size_of 32
```

Good:

```mojo
struct A:
    var b: Float64
    var d: Float64
    var a: Bool
    var c: Bool  # size_of 24
```

## MA122

`pow2-divmod` severity=low confidence=high risk=none (no semantic change)

Integer `x // 2**k` / `x % 2**k` in a loop: Mojo's floor semantics make these exactly `x >> k` and `x & (2**k - 1)` for every signed or unsigned value, but the compiler emits the sign fix-up sequence.

Why: floor // and Python-style % by 2^k equal arithmetic shift / mask for negatives too (-7 // 2 == -7 >> 1)

Bad:

```mojo
for i in range(n):
    s += xs[i] // 8 + xs[i] % 16
```

Good:

```mojo
for i in range(n):
    s += (xs[i] >> 3) + (xs[i] & 15)
```

## MA123

`python-in-loop` severity=medium confidence=high risk=none (no semantic change)

`Python.import_module()` / `Python.evaluate()` inside a loop: a CPython call (module dict lookup, object creation, refcounting) per iteration for a loop-invariant result. Do it once before the loop.

Bad:

```mojo
for i in range(n):
    var np = Python.import_module("numpy")
```

Good:

```mojo
var np = Python.import_module("numpy")
for i in range(n):
    ...
```

## MA124

`print-in-hot-loop` severity=info confidence=medium risk=none (no semantic change)

Unconditional `print` in the body of a nested loop: formatting plus a locked, flushed stdout write per inner iteration usually dominates the loop. Collect into a String and print once, or gate it.

Bad:

```mojo
for i in range(n):
    for j in range(m):
        print(i, j, x[i * m + j])
```

Good:

```mojo
var out = String()
for i in range(n):
    for j in range(m):
        out.write(i, ' ', j, ' ', x[i * m + j], '\n')
print(out)
```

## MA125

`repeated-pure-call` severity=low confidence=high risk=none (no semantic change)

The same call to a side-effect-free project function, with identical arguments, appears more than once in one expression: it is computed again (the compiler cannot prove purity across a non-inlined call).

Why: norm() walks the list twice; measured 2.0x on a 10k-element norm

Bad:

```mojo
acc += norm(xs) / (1.0 + norm(xs))
```

Good:

```mojo
var nv = norm(xs)
acc += nv / (1.0 + nv)
```

## MA126

`dict-iter-lookup` severity=medium confidence=high risk=none (no semantic change)

`for k in d:` followed by `d[k]` in the body: every iteration re-hashes a key it already holds (and `d[k]` can raise). Iterate `d.items()` and use `e.key` / `e.value`.

Why: one hash + probe per element saved; measured 6.6x on 20k String keys

Bad:

```mojo
for k in d:
    s += d[k]
```

Good:

```mojo
for e in d.items():
    s += e.value
```

## MA127

`sort-in-loop` severity=high confidence=high risk=none (no semantic change)

`sort(xs)` inside a loop that never changes `xs` otherwise: after the first iteration it re-sorts sorted data, O(n log n) (or O(n)) per iteration for nothing. Sort once before the loop.

Why: measured 162x for 2000 floats sorted 2000 times

Bad:

```mojo
for r in range(k):
    sort(xs)
    acc += xs[r]
```

Good:

```mojo
sort(xs)
for r in range(k):
    acc += xs[r]
```

## MA128

`huge-always-inline` severity=info confidence=medium risk=codesize (larger code / compile time)

`@always_inline` on a large function: every call site gets a full copy, inflating code size and compile time, and often hurting i-cache. Keep `@always_inline` for small leaves.

Bad:

```mojo
@always_inline
def step(...):  # 120 statements, called from 6 sites
```

Good:

```mojo
def step(...):  # let the inliner decide
```

## MA129

`gpu-sync-in-loop` severity=medium confidence=high risk=none (no semantic change)

A loop that only enqueues kernels and calls `ctx.synchronize()` each iteration: the host never reads results in between, so each sync is a full host/device round trip that serialises launches. Sync once after the loop (the stream is in-order).

Bad:

```mojo
for s in range(steps):
    ctx.enqueue_function[k](buf, grid_dim=g, block_dim=b)
    ctx.synchronize()
```

Good:

```mojo
for s in range(steps):
    ctx.enqueue_function[k](buf, grid_dim=g, block_dim=b)
ctx.synchronize()
```

## MA130

`gpu-uncoalesced` severity=low confidence=medium risk=api (signature change)

In a GPU kernel loop, `buf[tid * S + k]` with the thread index on the slow axis: neighbouring threads touch addresses `S` elements apart on every step, so each warp load splits into many transactions. Store the data transposed (`buf[k * N + tid]`) so a warp reads one contiguous segment.

Bad:

```mojo
var i = block_idx.x * block_dim.x + thread_idx.x
for k in range(K):
    s += X[i * K + k]
```

Good:

```mojo
for k in range(K):
    s += X[k * N + i]  # X stored transposed
```

## MA150

`copy-getter` severity=low confidence=medium risk=api (signature change)

A function whose result is `<field>.copy()` (or `<field>[key].copy()`) hands every caller a deep copy of a container it owns. Callers that only read pay an allocation and a memcpy of the whole container per call, and nothing at the call site says so. Return a borrow (take the value as a `ref` / pointer view), or offer a take / put pair for callers that need ownership for the length of one call.

Why: pm-simfast: a 20 MB label array copied per simulated cell, 4.9 ms of 42.9 ms (11.5%); gone with take / put

Bad:

```mojo
def lab(mut self, name: String) -> List[Int16]:
    return self.grps[name].copy()
```

Good:

```mojo
def lab_take(mut self, name: String) -> List[Int16]:
    return self.grps.pop(name)

def lab_put(mut self, name: String, var g: List[Int16]):
    self.grps[name] = g^
```

## MA151

`scattered-gather` severity=low confidence=low risk=none (no semantic change)

Inside a loop, several arrays are read at `row * width + j` where `j` itself comes out of an index list: every read lands on a different cache line of a different array. When the index lists and the arrays do not change between calls (a sweep over other knobs), gather the columns once into one contiguous struct-of-arrays table in walk order; each call then streams it. Confidence is low without a profile: it pays when the arrays are far larger than L2.

Why: pm-simfast: 9 scattered reads x 45 candidates x 1,702 nights per cell = 22.9 ms; 1.0 ms from a table built once

Bad:

```mojo
for q in range(b0[k], b0[k + 1]):
    var j = Int(bkj[q])
    acc += w[q] * (C[t * S + j] / O[t * S + j] - 1.0) - cost * adv[t * S + j]
```

Good:

```mojo
# once: tab.cmo[q] = C[t * S + j] / O[t * S + j] - 1.0; tab.adv[q] = adv[t * S + j]
for q in range(b0[k], b0[k + 1]):
    acc += w[q] * tab.cmo[q] - cost * tab.adv[q]
```

## MA152

`temp-struct-field-in-loop` severity=low confidence=high risk=none (no semantic change)

`make().field` inside a loop where `make()` builds a struct with a `String` or list argument: the whole struct is constructed (allocation included) and destroyed every iteration to read one scalar. Read the field once above the loop.

Why: pm-simfast: two String allocations per night x 1,702 nights per cell for one Float64

Bad:

```mojo
def s6() -> Cfg:
    return Cfg("s6", "sic2", 6, 0.5)

for k in range(n):
    gb[k] = book_g(W[k], s6().g)
```

Good:

```mojo
var gfix = s6().g
for k in range(n):
    gb[k] = book_g(W[k], gfix)
```

## MA153

`fresh-list-per-call` severity=low confidence=medium risk=api (signature change)

A helper that allocates a `List`, fills it and returns it (`return w^`) is called inside a loop: one allocation and one free per iteration that MA301 cannot see, because the constructor is in the callee. Give the helper a caller-owned output (a `mut` list it clears, or a pointer into a scratch buffer) and keep the returning wrapper for cold callers.

Why: pm-simfast: 53 k allocations per simulated cell (96% <= 256 B) from per-row / per-night helper results

Bad:

```mojo
def tilt(x: List[Float64]) -> List[Float64]:
    var w = List[Float64](length=len(x), fill=1.0)
    return w^

for k in range(nights):
    var w = tilt(xs[k])
    acc += w[0]
```

Good:

```mojo
def tilt_into(x: List[Float64], mut w: List[Float64]):
    w.resize(len(x), 1.0)

var w = List[Float64]()
for k in range(nights):
    tilt_into(xs[k], w)
    acc += w[0]
```

## MA154

`fma-chain-width` severity=low confidence=low risk=none (no semantic change)

An innermost loop whose body advances three to seven SIMD accumulators with `acc = x.fma(w, acc)`. Each accumulator is a dependency chain (4 cycles per FMA on Zen, 5 on Haswell / Broadwell, 4 on Skylake+) and the core has two FMA ports, so four chains can use at most 0.8-1.0 of the 2 FMA slots per cycle unless the out-of-order window overlaps neighbouring blocks. Widen the block to eight or more accumulators (16 ymm registers allow it). When every accumulator is its own output (a row of a product) the result is bit-identical; splitting one reduction into more accumulators is not.

Why: pm-simfast headfast z row: 4 -> 8 accumulators, same bits; see tests/simfast/RESULTS.md for the measured gain

Bad:

```mojo
for k in range(F):
    var xk = V(xr[k])
    z0 = xk.fma(w.unsafe_load[width=8](k * H), z0)
    z1 = xk.fma(w.unsafe_load[width=8](k * H + 8), z1)
```

Good:

```mojo
for k in range(F):
    var xk = V(xr[k])
    z0 = xk.fma(w.unsafe_load[width=8](k * H), z0)
    # ... z1 .. z6 ...
    z7 = xk.fma(w.unsafe_load[width=8](k * H + 56), z7)
```

## MA201

`unguarded-division` severity=medium confidence=medium risk=none (no semantic change)

Division by a runtime value that the function never compares, clamps or tests: an empty list, a zero sum, a flat bar (`h == l`) or a missing price (0.0) divides by zero. Float division silently yields inf/NaN that flows into weights and order sizes; Mojo `Int` division by zero returns 0 without trapping.

Why: a zero divisor turns into inf/NaN (Float) or 0 (Int) and propagates into sizing silently

Bad:

```mojo
var n = len(rets)
return s / Float64(n)
```

Good:

```mojo
var n = len(rets)
if n == 0:
    return 0.0
return s / Float64(n)
```

## MA202

`int-truncation` severity=medium confidence=medium risk=none (no semantic change)

`Int(float)` on a share count, notional or round-half-up idiom: `Int()` truncates toward zero, so `Int(x + 0.5)` rounds -2.7 to -2 and `Int(qty)` turns 2.9999999 (division noise) into 2 and -0.6 (fractional short) into 0.

Why: Int(Float64) truncates toward zero; sizes and signed deltas round the wrong way

Bad:

```mojo
var q = Int(target_usd / px)
var r = Int(x + 0.5)
```

Good:

```mojo
var q = Int(floor(target_usd / px + 1e-9))
var r = Int(floor(x + 0.5))
```

## MA203

`float-equality` severity=low confidence=medium risk=none (no semantic change)

`==`/`!=` between two computed floats, or against a literal that is not exactly representable (0.1, 1e-4): after any arithmetic the values differ in the last bits, so the branch flips on rounding noise. Exact sentinel literals (0.0, 1.0, -1.0, 0.5) are allowed; set `MA203.strict` to flag them too.

Why: computed floats rarely compare equal; 0.1 + 0.2 != 0.3

Bad:

```mojo
if w == target_w: skip()
if frac == 0.1: ...
```

Good:

```mojo
if abs(w - target_w) <= 1e-12 * max(abs(w), abs(target_w)): skip()
```

## MA204

`nan-compare` severity=low confidence=high risk=none (no semantic change)

Self-comparison `x != x` / `x == x` (the NaN idiom; always False/True for non-floats and removed by fast-math), and comparisons against a NaN value, which are always False.

Why: NaN compares unequal to everything, including itself

Bad:

```mojo
if x != x: continue
if y == nan[DType.float64](): ...
```

Good:

```mojo
if isnan(x): continue
if isnan(y): ...
```

## MA205

`math-domain` severity=medium confidence=high risk=none (no semantic change)

`sqrt`/`log` of an expression that can leave the domain: `sqrt(s2/n - mu*mu)` goes slightly negative from cancellation, `log(a - b)` hits 0, `log(p1 / p0)` with an unchecked data price returns -inf/NaN.

Why: NaN from a negative sqrt/log poisons every downstream sum, z-score and weight

Bad:

```mojo
var sd = sqrt(s2 / n - mu * mu)
r = log(px / prev)
```

Good:

```mojo
var sd = sqrt(max(s2 / n - mu * mu, 0.0))
r = log(px / prev) if px > 0 and prev > 0 else 0.0
```

## MA206

`int-true-division` severity=high confidence=high risk=none (no semantic change)

`Int / Int` converted to a float: in Mojo `Int.__truediv__` is floor division returning `Int` (7 / 2 == 3), so `Float64(a / b)` silently drops the fraction.

Why: Mojo Int / Int floors (7/2 == 3, -7/2 == -4); the float conversion happens after the fraction is gone

Bad:

```mojo
var frac = Float64(hits / total)
```

Good:

```mojo
var frac = Float64(hits) / Float64(total)
```

## MA207

`one-sided-tolerance` severity=medium confidence=medium risk=none (no semantic change)

`a - b < eps` without `abs()`: true for every `a` far below `b`, so a "close enough" test passes for wildly different values.

Why: a - b < eps holds for any a < b, not just a ~= b

Bad:

```mojo
if px - target < 1e-9: done = True
```

Good:

```mojo
if abs(px - target) < 1e-9: done = True
```

## MA208

`swapped-clamp` severity=high confidence=high risk=none (no semantic change)

`min(max(x, A), B)` with A > B (or `max(min(x, A), B)` with A < B, `clamp(x, hi, lo)`): the result is the constant B regardless of x.

Why: with crossed bounds the clamp ignores its input and always returns one bound

Bad:

```mojo
var w = min(max(x, 1.0), -1.0)
```

Good:

```mojo
var w = min(max(x, -1.0), 1.0)
```

## MA209

`suspicious-identity` severity=high confidence=high risk=none (no semantic change)

Self-assignment `x = x`, identical operands (`a - a`, `a / a`, `x < x`, `c and c`), and `t if c else t`: almost always a typo for a different variable (go vet / staticcheck SA4000).

Why: the expression is constant; the intended second operand is missing

Bad:

```mojo
self.qty = self.qty
var spread = ask - ask
```

Good:

```mojo
self.qty = qty
var spread = ask - bid
```

## MA210

`duplicate-condition` severity=high confidence=high risk=none (no semantic change)

The same condition twice in one `if`/`elif` chain: the later branch can never run.

Why: the first matching branch wins, so the duplicate branch is dead code

Bad:

```mojo
if side == 1:
    buy()
elif side == 1:
    sell()
```

Good:

```mojo
if side == 1:
    buy()
elif side == -1:
    sell()
```

## MA211

`identical-branches` severity=medium confidence=medium risk=none (no semantic change)

`if`/`else` (or a whole `if`/`elif`/`else` chain) whose branches have identical bodies: the condition has no effect, usually because one branch was copied and not edited (clippy if_same_then_else).

Why: both paths do the same thing; the branch that should differ was not edited

Bad:

```mojo
if side > 0:
    px = bid
else:
    px = bid
```

Good:

```mojo
if side > 0:
    px = ask
else:
    px = bid
```

## MA212

`unreachable-code` severity=medium confidence=high risk=none (no semantic change)

Statements after `return`/`raise`/`break`/`continue` in the same block never execute.

Why: code after an unconditional exit is dead; often a misplaced log/flush/state update

Bad:

```mojo
return pnl
log_fill(pnl)
```

Good:

```mojo
log_fill(pnl)
return pnl
```

## MA213

`edge-index` severity=high confidence=high risk=none (no semantic change)

Index `xs[i - k]` in a loop starting at 0 (or `xs[i + k]` in a loop to `len(xs)`) with no test on `i`, and `range(len(xs) + 1)` / `xs[len(xs)]`: out of bounds on the first or last iteration. Mojo's `List` asserts on a negative index (crash), and with assertions off reads outside the buffer.

Why: first/last iteration indexes outside the list

Bad:

```mojo
for i in range(len(px)):
    r[i] = px[i] / px[i - 1] - 1.0
```

Good:

```mojo
for i in range(1, len(px)):
    r[i] = px[i] / px[i - 1] - 1.0
```

## MA214

`discarded-status` severity=medium confidence=medium risk=none (no semantic change)

`_ = f(...)` discarding a `Bool` success flag of an action (submit/cancel/send/write...) or the byte count of a raw write: a failed order/cancel or a partial write goes unnoticed.

Why: the call reports failure through its return value, which is thrown away

Bad:

```mojo
_ = cancel_order(http, oid)
_ = c_write(fd, buf, n)
```

Good:

```mojo
if not cancel_order(http, oid):
    log_err(oid)
write_all(fd, buf, n)
```

## MA215

`unit-scale` severity=medium confidence=low risk=none (no semantic change)

A `*bps*` value used in arithmetic with no 1e4 / 1e-4 scaling in the statement, or `1 + pct` with no 1/100 scaling: off by 10000x / 100x (heuristic).

Why: basis points are 1/10000; mixing them with fractions misprices by 10000x

Bad:

```mojo
var fill = px * (1.0 + slip_bps)
```

Good:

```mojo
var fill = px * (1.0 + slip_bps * 1e-4)
```

## MA301

`alloc-in-loop` severity=medium confidence=high risk=none (no semantic change)

A `List`/`Dict`/`Set`/`String` declared inside a loop and grown there allocates (and frees) its buffer every iteration. Hoist the declaration above the loop and reset it in place (`clear()`, `resize(0)` for String): capacity is kept, so after the first iteration no allocation happens. Also `alloc[T](n)` freed in the same iteration. Risk: the buffer's peak capacity stays live until the loop ends.

Why: each iteration pays malloc + free (+ regrowth copies); measured 20.0M -> 101 allocations, 5.4x

Bad:

```mojo
for i in range(n):
    var row = List[Float64]()
    for j in range(k):
        row.append(x[i + j])
```

Good:

```mojo
var row = List[Float64]()
for i in range(n):
    row.clear()
    for j in range(k):
        row.append(x[i + j])
```

## MA302

`invariant-alloc-in-loop` severity=medium confidence=high risk=none (no semantic change)

An allocating call (`.split()`, `String(x)`, `.copy()`, `.upper()`, `.join()`, ...) whose operands do not change inside the loop, and whose result is only read: it builds the same heap value every iteration. Compute it once before the loop.

Why: the same heap object is rebuilt per iteration; measured 200k -> 1 allocation, 57x

Bad:

```mojo
for i in range(n):
    var cols = header.split(",")
    t += len(cols[i % 8])
```

Good:

```mojo
var cols = header.split(",")
for i in range(n):
    t += len(cols[i % 8])
```

## MA303

`missed-move` severity=medium confidence=high risk=none (no semantic change)

`x.copy()` where this is the last use of the local `x`: the deep copy (allocation + memcpy) is thrown away immediately after. Transfer ownership with `x^` instead.

Why: the source dies right after, so the copy is pure overhead; measured 40001 -> 20001 allocations

Bad:

```mojo
var row = make_row(i)
rows.append(row.copy())
```

Good:

```mojo
var row = make_row(i)
rows.append(row^)
```

## MA304

`copy-read-only` severity=low confidence=high risk=none (no semantic change)

`var y = e.copy()` (outside a loop; MA109 covers loops) where `y` is only read and `e` is not mutated while `y` is alive: bind a reference (`ref y = e`) and skip the deep copy.

Bad:

```mojo
var cfg = self.cfg.copy()
return cfg.n * 2
```

Good:

```mojo
ref cfg = self.cfg
return cfg.n * 2
```

## MA305

`dict-key-rebuilt` severity=low confidence=high risk=none (no semantic change)

The same String key is built (concatenation / `String(...)`) for several lookups of one `Dict` in the same block: each build allocates and each lookup rehashes. Build the key once.

Bad:

```mojo
if s + ":" + t in d:
    d[s + ":" + t] += 1
else:
    d[s + ":" + t] = 1
```

Good:

```mojo
var key = s + ":" + t
if key in d:
    d[key] += 1
else:
    d[key] = 1
```

## MA306

`nested-list-rows` severity=low confidence=medium risk=api (signature change)

`List[List[T]]` of fixed-length numeric rows: one heap block per row (n+1 allocations, rows scattered in memory, two dependent loads per element). Use one flat `List[T](length=n*k)` indexed `i*k + j`.

Bad:

```mojo
var m = List[List[Float64]]()
for i in range(n):
    m.append(List[Float64](length=k, fill=0.0))
```

Good:

```mojo
var m = List[Float64](length=n * k, fill=0.0)  # m[i * k + j]
```

## MA307

`small-writes-in-loop` severity=medium confidence=high risk=none (no semantic change)

`f.write(...)` on a `FileHandle` inside a loop: every call is a separate `write(2)` syscall. Build the output in a `String` with `buf.write(...)` and write it once (or in large chunks).

Bad:

```mojo
with open(p, "w") as f:
    for i in range(n):
        f.write(i, "\n")
```

Good:

```mojo
var buf = String()
for i in range(n):
    buf.write(i, "\n")
with open(p, "w") as f:
    f.write(buf)
```

## MA308

`dict-capacity` severity=low confidence=high risk=none (no semantic change)

Empty `Dict` filled by one unconditional insert per iteration of the loop right after it, with a known trip count: pass `capacity=` so the table is sized once instead of rehashing as it grows.

Bad:

```mojo
var d = Dict[Int, Int]()
for i in range(n):
    d[i] = f(i)
```

Good:

```mojo
var d = Dict[Int, Int](capacity=n)
for i in range(n):
    d[i] = f(i)
```

## MA309

`list-bool-bitset` severity=info confidence=low risk=api (signature change)

`List[Bool]` of a compile-time-known size: one byte per flag on the heap. `BitSet[N]` stores 8 flags per byte inline (no allocation). Info only: bit access costs a shift/mask.

Bad:

```mojo
var seen = List[Bool](length=256, fill=False)
```

Good:

```mojo
var seen = BitSet[256]()
```

## MA401

`removed-keyword` severity=high confidence=high risk=none (no semantic change)

`fn`, `let` and `alias` were removed (Mojo 1.0): the file does not parse. `fn` is still reserved, so it cannot be used as a variable or argument name either.

Bad:

```mojo
fn f(x: Int) -> Int:
    let y = x
alias N = 4
```

```mojo
def f(x: Int) -> Int:
    var y = x
comptime N = 4
```

## MA402

`removed-convention` severity=high confidence=high risk=none (no semantic change)

Argument conventions `owned`/`inout`/`borrowed` and the `read` capture convention were removed; `out` is reserved and cannot name an argument. The signature does not parse.

Bad:

```mojo
def f(owned a: List[Int], inout b: Int, out: Int): ...
def g() {read x}: ...
```

Good:

```mojo
def f(var a: List[Int], mut b: Int, res: Int): ...
def g() {imm x}: ...
```

## MA403

`parameter-decorator` severity=high confidence=high risk=none (no semantic change)

`@parameter for` / `@parameter if` no longer parse ("statement does not support decorators"): use `comptime for` / `comptime if`. `@parameter` on a nested `def` still compiles but is deprecated.

```mojo
    ...
```

## MA404

`bare-std-import` severity=high confidence=high risk=none (no semantic change)

The standard library is namespaced under `std.`: `from math import sqrt` fails with "unable to locate module 'math'" unless a local module of that name exists.

## MA405

`removed-name` severity=high confidence=high risk=none (no semantic change)

Builtins, types and decorators that were renamed or removed by Mojo 1.x (`sizeof`, `str()`, `DTypePointer`, `StringRef`, `Stringable`, `@value`, `@register_passable`, `memset_zero`, ...): "use of unknown declaration". Names the file defines itself are skipped.

Bad:

```mojo
@value
struct P:
    var x: Int
def f(x: Int) -> String:
    return str(sizeof[Int]())
```

Good:

```mojo
@fieldwise_init
struct P(Copyable, Movable):

    return String(size_of[Int]())
```

## MA406

`removed-method` severity=high confidence=high risk=none (no semantic change)

Methods that changed shape: `UnsafePointer[T].alloc(n)` (now `alloc[T](n)`), `List.capacity` (now a method, `capacity()`), SIMD/scalar `.min()`/`.max()` (free `min`/`max`). `String.reserve` is deprecated in favour of `reserve_bytes`.

Bad:

```mojo
var p = UnsafePointer[Int].alloc(n)
var c = xs.capacity
var m = a.max(b)
```

Good:

```mojo
var p = alloc[Int](n)
var c = xs.capacity()
var m = max(a, b)
```

## MA407

`string-len-index` severity=high confidence=high risk=none (no semantic change)

`len(s)` and positional `s[i]` on a `String` are compile errors (UTF-8 makes "length" ambiguous): use `s.byte_length()` and `s[byte=i]` (or `codepoints()` / `s[codepoint=i]`).

```mojo
var s = String("abc")
var n = len(s)
var c = s[0]
```

Good:

```mojo
var s = String("abc")
var n = s.byte_length()
var c = s[byte=0]
```

`f-string` severity=high confidence=high risk=none (no semantic change)

## MA410

`simd-eq-scalar` severity=medium confidence=medium risk=none (no semantic change)

`a == b` on SIMD vectors of width > 1 returns one `Bool` (all lanes equal), not a lane mask. Binding it to a variable usually means a mask was intended: use `a.eq(b)` (and `.ne/.lt/.le/.gt/.ge`).

Why: SIMD(1,2,1,3) == SIMD(1) is False, not [True, False, True, False]

Bad:

```mojo
var m = a == b  # a, b: SIMD[DType.float32, 4]
```

Good:

```mojo
var m = a.eq(b)
```

## MA411

`deprecated-pointer-api` severity=low confidence=high risk=none (no semantic change)

Deprecated in 1.2 (warnings today, errors later): `UnsafePointer` -> `Pointer`, `p.load`/`p.store` -> `unsafe_load`/`unsafe_store`, `p.free()` -> `p.unsafe_free()`, positional `p[i]` -> `p[unsafe_offset=i]`.
